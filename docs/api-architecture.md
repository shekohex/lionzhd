# External API Architecture

The external API is additive to the Inertia web app and is mounted under `/api/v1`. Routes use `auth:sanctum`, `throttle:api`, and `AcceptJsonApi`, so callers authenticate with personal access tokens and receive JSON:API responses.

API controllers should stay thin. They map requests to existing actions, policies, DTOs, and models, then return Laravel `JsonApiResource` responses. Business behavior shared with the web UI belongs in actions such as `ManageSeriesMonitoring`, `ApplySeriesMonitoringPreset`, and `UpdateUserSettings`.

Responses should use `application/vnd.api+json` with resource objects containing `id`, `type`, and `attributes`. Paginated resources should expose `links` and `meta`. Do not return plaintext infrastructure credentials; admin settings responses use credential-present booleans for write-only secrets.

OpenAPI documentation is generated by Scramble at `/docs/api` and `/docs/api.json`. Prefer route-specific controller methods and API FormRequest classes so Scramble can infer accurate request schemas.

Operational boundaries:

- API routes are versioned under `/api/v1`.
- Auth flows and profile deletion are not exposed externally.
- Existing web routes must not change behavior when API endpoints are added.
- Mutating API endpoints should use API FormRequests for JSON:API validation errors.
- Side-effecting controllers should call shared actions rather than duplicating web controller logic.
